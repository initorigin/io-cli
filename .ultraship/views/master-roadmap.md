# Master roadmap

## io-cli

| Version | Outcome | Detail | Status |
| --- | --- | --- | --- |
| 0.1.0 | A developer with no configuration runs `io` in a repository and reaches a finished task in the same session. A guided first run asks for a provider, takes a key and verifies it against the live endpoint, offers the provider's models, previews the themes as it moves between them, and picks a default permission posture — then writes io-harness's own configuration file. The session that follows renders on a hybrid inline viewport: every finished turn, tool cell and message is committed into the terminal's real scrollback, and only a short pane at the bottom holds the composer and the status line. The developer types a task, watches the answer stream, watches a file get edited inside the sandbox, interrupts with a keystroke, and exits — leaving the whole conversation scrollable, searchable and selectable with the terminal's own facilities, because io-cli never took them away. | specified | released |
| 0.1.1 | The session stops looking frozen while it works. A turn in flight shows a moving indicator beside the word that names its state, so a reader can tell thinking from hung, and the elapsed clock advances on its own rather than only when an event happens to arrive. A step reads as a step — what the agent decided, what it ran, and what came back — instead of a decision string with a token count appended to it. The README gains the screenshot 0.1.0 could not supply, taken from a run of the corrected interface. Nothing about the permission boundary, the renderer or the wizard changes: this is the release that makes what 0.1.0 already does legible while it is happening. | specified | released |
| 0.2.0 | The operator can see and steer the boundary the agent is working under. One key cycles the permission posture and the status line names the io-harness policy layer now in force. A sensitive action stops the run in an overlay that cannot scroll away — showing the act, the target, the rule and layer that are asking, and the content a write proposes — and is resolved by keystroke into both the transcript and the durable trace. A refusal prints the act, the target, and the rule and layer that produced it, which no other terminal agent can render because no other core records it. The status line gains the fields the harness can supply to a steerable turn: the policy layer, tokens, context pressure, containment. | specified | planned |
| 0.3.0 | The operator can read what the agent did without leaving the terminal or losing the thread. Edits render as diffs — unified by default, word-level emphasis inside changed lines, syntax highlighting, context collapsed with an expander, a defined form for narrow terminals, and a minimal mode for people who review by file rather than by hunk. Tool calls render as one line with a result and a duration, expandable while live and committed collapsed, with the full output going to the durable trace rather than to the screen. A transcript overlay gives the whole conversation on one key, and the last message or the last diff can be put on the system clipboard in a way that survives SSH. | outline | planned |
| 0.4.0 | Work survives the session. A picker lists previous sessions from the harness store and reopens one where it stopped. Any turn in a conversation can be forked into a new branch and continued from there. The model can be changed mid-session without losing context. An empty composer takes a double-escape to rewind the conversation and the workspace to an earlier point, using the rewind the harness already implements and already records. | outline | planned |
| 0.5.0 | The same agent runs unattended. A non-interactive subcommand takes a goal, runs it to completion, and exits with a meaningful status; with a flag it emits the run's events as newline-delimited JSON — the same events the interactive session renders, from the same stream, with no interface code on the path. Sandbox and policy are selectable from the command line, a non-TTY stdout is detected and honoured without being asked, and credentials are taken from the environment so nothing has to be written to disk in CI. | hypothesis | planned |
| 0.6.0 | The interface reaches people and terminals the category currently excludes. A plain mode built for screen readers removes animation and repaint, keeps the real terminal cursor as the focus indicator, puts content before metadata, and announces every state change as one line of text — which no terminal agent in this field does today. Colour is never the sole carrier of meaning, `NO_COLOR` is honoured, box drawing degrades to ASCII, the keyboard protocol is negotiated up on terminals that advertise it and down over SSH without losing core function, keybindings are configurable and documented as a table, and every surface has an audited form at eighty columns. | hypothesis | planned |
| 0.7.0 | The composer becomes a command surface. A slash palette with fuzzy matching reaches every command and every harness skill and prompt template; `@` completes paths from the workspace; `!` passes a line to the shell verbatim; a large paste becomes an attachment instead of flooding the input. Every picker filters as you type — the model list, the theme list, `/resume` and `/fork` — so a four-hundred-model catalogue is reached by typing three characters rather than by holding an arrow key. The agent's own plan and todo list render as a live panel, and a question the agent asks about intent — which the harness distinguishes from an approval about permission — is answered inline rather than guessed at. | hypothesis | planned |
| 0.8.0 | A decomposed task becomes visible as a tree. Spawned children appear as a live fleet with their own status, each showing its draw against the ceiling the whole tree shares, with refused spawns and collected results shown where they happen. The status line gains the spend field here rather than at 0.2.0: `SpendDraw` is emitted only by a contained turn, and the contained entry point takes no steer inbox, so a session that renders spend today is one that cannot be interrupted. This release is contained by definition, which is what makes the field reachable. This is the surface that is structurally impossible for a competing interface to copy, because it is rendering facts only this core emits. | hypothesis | planned |
| 0.9.0 | The remaining harness capabilities get a face. Images render inline where the terminal speaks Kitty, iTerm2 or Sixel and degrade to half-blocks where it does not, and an image can be attached to a turn. Background shell handles, browser sessions, LSP servers and MCP servers each get a compact live indicator, so a run that has started something long-lived says so rather than appearing idle. | hypothesis | planned |
